## 映射规则

为每个候选建立 `target_index_mapping` 记录，至少包含：

- `display_name`
- `original_code`
- `canonical_code`
- `canonical_name`
- `category`
- `data_source`
- `mapping_status`
- `mapping_note`
- `included`
- `exclusion_reason`

`mapping_status` 只允许：

- `EXACT`：公开数据源能够取得截图中的同一指数或板块。
- `PUBLIC_EQUIVALENT`：存在能够通过官方名称、代码和编制方案明确确认的等价指数。
- `UNSUPPORTED`：不使用同花顺数据时无法找到可靠对应数据，或数据条件不足。

代码前缀规范化不改变标的身份。例如 `SZ399006` 映射到公共源代码 `399006` 仍属于 `EXACT`。

仅名称相似、编制方法不同的指数不得定义为 `PUBLIC_EQUIVALENT`。不得为了增加成功数量而替换候选标的。

## 数据源边界

公开数据核验优先级为：中证指数、国证指数、上交所、深交所、北交所、港交所或恒生指数公司，以及这些来源对应的 AKShare 公开接口。

本阶段禁止调用同花顺 API 或 AKShare 中以同花顺板块数据为底层来源的接口。HY/GN 代码只有在其他公共官方来源能够证明同一标的身份时才能映射，否则标记 `UNSUPPORTED`。

不新增需要 API Key 的数据源。

## 可行性检查

每个候选分别记录以下检查结果和证据：

1. 约3年日行情是否可取得；
2. 当前成分股是否可取得；
3. 成分股约3年历史行情是否存在可运行的数据路径；
4. 是否具备计算 RET20、BIAS20、RS20、VolumeStrength、BreadthMA20、HLBreadth、Sync 的字段；
5. 数据源的实际小范围请求是否稳定。

本阶段只做小范围探测，不执行新增标的的全量历史抓取。任一必要条件不满足时，标记 `UNSUPPORTED` 并继续处理其他候选。

只有第一阶段判断可行且经用户确认的标的，才进入第二阶段完整抓取和模型验证。

## 数据库与现有版本保护

第一阶段不修改 `data/market.duckdb`，因此不需要数据库写入备份。第二阶段开始写入前必须创建数据库备份并核对摘要。

以下内容在全部阶段保持冻结：

- V1.0 公式和权重
- V1.1 公式和权重
- 沪深300基准
- 温度阈值
- 状态定义

## 第一阶段输出

生成 `output/watchlist_mapping.xlsx`，至少展示：

- 用户自选名称
- 截图代码
- 实际使用代码
- 实际指数名称
- 类别
- 数据源
- 映射状态
- 纳入或排除
- 排除原因
- 五项可行性检查
- 核验说明和来源链接

工作簿须通过内容检查、公式错误检查、UTF-8 中文文本检查和全部工作表视觉检查。

## 第一阶段汇报顺序

完成后先汇报：

1. 21个候选中 `EXACT`、`PUBLIC_EQUIVALENT`、`UNSUPPORTED` 的数量；
2. 21个标的逐项映射结果和数据源；
3. 无法在当前公开数据体系中取得的 HY/GN 标的；
4. 可进入第二阶段的候选清单及其可行性边界。

未获得用户确认前，不开始第二阶段批量计算。
